**AI prototyping** is the practice of using AI coding assistants to translate your design intentions — layouts, user flows, interaction patterns, visual style — directly into working, interactive code. Instead of handing wireframes off to a developer and waiting days for a first build, you describe what you want and the AI generates a functional mockup you can click through, test, and iterate on immediately. The result is a dramatically shorter cycle from design concept to testable prototype, giving you more time to focus on what matters most: validating ideas and improving the user experience.

<Note>
  You don't need to be a developer. AI prototyping is about describing your design intent clearly — the AI handles the code.
</Note>

---

## Traditional vs. AI-Assisted Prototyping

| | **Traditional Prototyping** | **AI-Assisted Prototyping** |
|---|---|---|
| **Speed** | Days or weeks from concept to interactive build | Hours from description to working prototype |
| **Output** | Static wireframes or limited clickable mockups | Interactive, code-based prototypes |
| **Control** | Designer depends on developer for changes | Designer drives iteration directly |
| **Iteration** | Lengthy handoff cycles for each revision | Refine in real time with follow-up prompts |
| **Fidelity** | Low-to-medium fidelity until late in the process | High fidelity from the very first generate |
| **Collaboration** | Feedback loops slowed by availability of developers | Stakeholders can interact with prototypes immediately |

## How It Works

AI prototyping follows a simple three-step loop you'll return to again and again throughout this guide.

### 1. Describe

You write a prompt — in plain language — that explains what you want the AI to build. This might be a navigation bar, a user registration form, an onboarding flow, or a full dashboard layout. The more clearly you describe your design intent (colors, layout, interactions, component names), the better the output. You'll learn exactly how to write effective prompts in the [Design to Prompt Workflow](/workflow/design-to-prompt).

### 2. Generate

The AI coding assistant — GitHub Copilot, Claude, Cursor, or another tool — takes your description and produces code: HTML, React, Vue, or whichever framework fits your project. You don't need to read or understand every line. What you care about is whether the output matches your design intent, and whether it behaves the way users should experience it.

### 3. Refine

Rarely is the first output exactly right — and that's perfectly normal. You review the result, identify what needs to change, and write a follow-up prompt to adjust it. Move a button, change the color scheme, add an animation, restructure a layout. Each refinement cycle is fast, and over a few iterations, the prototype converges on your vision.

## Why GitHub?

GitHub is more than a place to store code — it becomes your **design system memory** and **collaboration hub** when you work this way.

- **Store prompt templates**: Save the prompts that produced great results so you can reuse and refine them across projects.
- **Track every version**: Every time you regenerate or tweak a prototype, you can commit the change. That means you can always roll back to an earlier version or compare iterations side by side.
- **Collaborate with your team**: Share a repository link and teammates — including developers — can view, comment on, or even extend your prototype.
- **Document your workflow**: Commit messages and README files let you document why decisions were made, making handoff to development far smoother.

You don't need to be a Git expert. This guide covers everything you need in [Set Up Your Environment](/getting-started/setup).
